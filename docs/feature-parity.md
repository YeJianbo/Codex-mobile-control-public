# ChatGPT、Codex 与 Harness 功能核对

核对日期：2026-10-18。目标是让同一项操作在 Android、Web 和不同执行器上保持一致；模型本身的质量、上游授权、服务容量和原生未开放的接口单独记录。

“已实现”表示已找到对应执行路径，不代表本轮全部实测。“部分”表示入口存在但能力或范围不齐；“缺失”表示本项目还没有对应产品功能。实际测试结果在文末单列。当前不能称为与 ChatGPT、Codex 全功能完全一致。

## 官方核对来源

- [Codex 移动端](https://learn.chatgpt.com/docs/mobile)：远程连接、任务列表、审批、发送指令和检查结果。
- [手机远程开发工作流](https://developers.openai.com/blog/mastering-codex-remote-for-engineering)：工作树、目标、运行中引导、排队、附件和审阅。
- [ChatGPT 功能索引](https://learn.chatgpt.com/docs/features)、[使用方式](https://learn.chatgpt.com/docs/use-chatgpt)、[项目与会话](https://learn.chatgpt.com/docs/projects)：通用对话、Work、项目、文件和工具。
- [Codex 客户端协议](https://developers.openai.com/blog/codex-as-a-platform)：线程、轮次、事件与审批的执行器边界。

初轮协议与适配检查 39 项通过，最终受影响的协议组 35 项通过。签名公网设备检查通过，覆盖默认 7 个 Harness、独立开关、并发保存、未签名拒绝和已有权限边界；置顶及提交回执 7 项通过。未读回归覆盖各 Harness 的新完成、已读、再次完成和旧回执不清掉新未读。

Android 模拟器检查：公网开关、通知布局、两种选文、已读行为与前台静默 6 项通过；旧 Harness 切换测试误把打开连接页当成强制目录刷新，改为显式“重新检查”后，Harness 切换与设置导航 2 项复测通过。测试使用独立包和模拟设备，未在实体手机验收。

Chrome 检查发现底层预先翻译写入权错误，导致提交回执及队列漏识别。修复为保留原始 RPC 错误，自动排队与释放后发送已实测通过。旧文件测试改为从右上角“工作区文件”进入，文件编辑保存、中文路径 diff、终端停止与预览检查通过。

完整浏览器54项中51项通过；旧云快照、Harness和子代理场景修正后定向复测通过：快照导入/重试/竞态/取消4项，Harness模型读回/续聊/停止/长文本/公网开关5项，子代理返回/菜单关闭/搜索及页面错误、云任务3组通过。没有宣称在最后一次命令中重跑并通过54项。浏览器Harness使用模拟CLI；上表单列真实CLI的4/6结果。测试现先构建并运行正式dist，默认工作区也固定在临时目录。另修复手机网页空会话时工具入口被隐藏的问题，固定顶栏支持直接进入工作区文件。

原始记录保存在本机 `D:/codex/build/Codex-mobile-control/harness446-*.log`、`harness-live/` 和通知截图中。最终构建、浏览器与模拟器结果以本轮工作状态的最终记录为准；上表失败项不因协议夹具通过而改成成功。

## 仍需补齐

其他 Harness 的持久目标、定时任务、原生回滚编辑、直接 steer、自定义沙盒和子代理控制，是与 Codex 尚未相同的主要执行能力。语音、云执行、ChatGPT 项目记忆及专用产物工作台是独立产品能力，当前没有实现成等价功能。应逐项接入真实接口或网关执行机制后再验收，不能仅增加按钮或改标签。
