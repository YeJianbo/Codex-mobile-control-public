# Android 0.6.147/code170 / Gateway 0.6.60

修复流式输出前文消失和更新时阅读位置跳动。手机需覆盖安装同签名 APK；本机正式网关已经更新。

## 原因与修复

- 旧服务端仅保留全局最近 1,000 个通知，并只取当前会话最近 200 条事件。长回复的开头会被片段数量上限截掉；其他会话输出也会挤掉本会话的实时事件。
- 手机历史刷新原先用整批快照替换已显示内容，只补回请求发出后收到的通知。早于请求的实时前文无法保留，迟到的快照也可能使正文退回短版本，引发高度变化和滚动跳动。
- 网关增加独立 SQLite 实时历史窗口：每个会话保留最近两轮完整对话，按用户消息或桌面轮次起点淘汰整轮。重连通知环仍为 1,000 条。磁盘缓存目标为最多 64 个非运行会话、32 MiB；运行中及刚更新的当前会话完整保留，允许临时超出预算，结束后在后续轮次维护时淘汰旧窗口。数据库读取不常驻全部正文。已有 Android 会话缓存仍为 8 个、估算 12 MiB。
- 默认历史窗口若落在同一消息的流式片段中间，向前保留该消息的全部片段。默认、count 和 turns 三种读取方式都检查完整正文，不以片段数量截断回复。
- 重启时只为尚无独立窗口的会话补入通知环，避免被淘汰的旧片段重新插到新回复后面。删除会话同步清理独立窗口。
- 自动目标连续轮次没有新用户消息时，也按轮次起点保留窗口，不因共用最初的提示而保留全部旧输出。
- 历史读取还合并重连环中仍保留的旧事件，保留先前上传附件和操作记录的身份；与完整窗口按事件 ID 去重，旧页面的附件和操作读取不因窗口缩短而提前失效。
- Android 按消息 itemId、事件 ID 和顺序合并历史与已显示事件，保留旧快照遗漏的前缀和后缀；完整日志替换同一消息的实时片段，不重复追加。相同文字的多个真实片段不按文本去重。较短的前缀快照不能回退已收到的正文。
- 完整保存的消息显式标记 `textComplete`，可纠正旧页面已经重复追加的尾段；服务端与手机忽略该 item 后续迟到的片段，其他新 item 正常接收。未完成快照和部分后缀同时返回时，整段正文只合并一次，并保留片段 ID。手机另保留最多 16,000 个输出事件身份，防止历史替换后同一通知再次追加；重新连接时清空。
- 只读云快照使用带版本时间的事件 ID，按最新快照替换，不补回旧版本的正文。本地有实时输出的会话才进行增量合并。
- 滚动回调只在用户直接向下阅读并到达末尾时恢复跟随，惯性或布局更新不能自行开启跟随。保留回到最新、末尾跟随和加载更早记录的行为。

## 失败与恢复记录

测试首轮退出码 1：测试文件同时导入两个 Dispatcher，编译失败，改为明确 MockWebServer 类型。补充后缀回归首轮退出码 1：Kotlin 测试的多变量声明用了逗号，编译失败；改为独立声明后回归通过。第二轮退出码 1：fixture 在主线程解析 MockWebServer 地址，触发 NetworkOnMainThreadException；将地址准备移出主线程后最终 6/6 通过。没有改动产品网络线程策略来绕过检查。

部署脚本首轮退出码 1：Windows PowerShell 5.1 读取不带 BOM 的中文 UTF-8 时发生字符串解析错误，尚未执行部署。补齐 BOM 后退出码 0。部署仅重启本机网关进程，原桌面 Codex、共享桥接和公网入口继续运行。

Gradle 完成后卸载隔离测试应用，首次提取截图退出码 1，提示文件不存在。用相同隔离 APK 直接执行两项 instrumentation，2/2 通过，成功提取并查看截图。首轮失败不计入有效验收。
