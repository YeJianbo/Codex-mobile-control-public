# Android 0.6.145/code168 / Gateway 0.6.56

中断目标通过 `thread/goal/set` 保存为 paused，面板显示“已暂停”。用户点击独立“继续”按钮后，网关恢复目标并发送一条可见的“继续”指令，实际启动新一轮；沿用当前模型、思考等级、模式、快速模式和权限。目标内容、累计时间、草稿和已有队列保留。

## 实现与行为

- 后台核对确认 interrupted/error 且实际线程 idle/notLoaded 时，暂停仍 active 的目标。后台仍 active 或状态读取结果不明时不误暂停。目标数据库只读，写入通过 Codex API。
- 用户停止轮次时先暂停 active 目标，防止目标调度器在中断完成后立即启动下一轮。普通“暂停目标”操作保留当前轮次；当前轮次结束后可点击“继续”。
- `POST /api/threads/:threadId/goal/continue` 复用现有发送流程、目录权限核对、模型校验和持久请求回执。同一请求重复提交或并发重复点击不会重复启动；暂停与继续的并发操作等待状态写入完成。已经运行的线程拒绝第二次启动。
- 明确启动拒绝时，目标恢复暂停。超时且后台仍实际 active 时不重发指令；状态核对保留实际运行。进行中侧栏仍只按会话及子代理的实际运行状态生成。
