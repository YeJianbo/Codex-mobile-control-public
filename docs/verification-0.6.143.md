# Android 0.6.143/code166 / Gateway 0.6.53

本轮由主线程亲自调试 AGY、Claude Code 和 Grok Build 的真实 CLI、Web 及 Android 链路。隔离目录内使用合成标记和文件；未修改模型账号、代理地址或用户的全局 CLI 权限配置。

## 修复

- Grok 的 ACP 回答分片此前被 Claude 完整消息去重规则吞掉，导致只显示首个分片。现在按各自协议处理；恢复历史时跳过 ACP 重放，结束时等待输出流排空。
- Grok 使用已发现或明确配置的 CLI 路径；每次启动显式传入手机选择的权限，覆盖本机 CLI 的默认 always-approve。续聊重新应用配置模型及推理强度，修复自定义模型别名恢复后误走官方路由的 401。正常停止使用 ACP 取消，超时才终止所属进程树，并等待退出。
- Claude/Grok 模型及推理强度从无提示词的初始化握手读取。保留别名与解析模型的区别；Grok 的实际模型及用量取自最终响应，Claude 补齐缓存创建输入和上下文窗口统计。
- 成功的文件编辑进入已有变更卡片；Claude/Grok 有结构化差异时显示真实补丁及增删行，失败或拒绝的工具不报告文件已修改。AGY 本轮只提供文件路径，未虚构补丁。
- Android 不再丢弃 AGY/Claude 的计划模式；Claude 将 plan 传入 CLI 权限模式。Grok 当前 ACP 未提供计划切换，外部后端未提供统一快速模式，这些入口返回明确说明，避免显示已开启却无效。
- Claude AskUserQuestion 通过现有问题卡片收集答案并回传，停止时取消待答问题。Grok 的真实提问探测没有调用提问工具，只返回文本，因此本轮不声称其结构化提问已验证。
- 图片能力取自后端声明。当前 AGY 与 Grok 不接受图片消息，客户端提示改用文件附件；不把图片静默丢弃，也不因已知不支持的输入创建空会话。

## 验证

- Node 265/265；网关 smoke 37/37；Web 53/53；Android JVM 181/181。Release、隔离 Debug 和 instrumentation APK 构建成功；lint 0 errors / 25 warnings。发布签名延续上一版。
- 原生后端定向 7/7，覆盖 Claude/AGY/Grok 发送、续接、停止，AGY 长流恢复、计划模式参数和不可用入口。真实原生用例另 1/1：依次打开三个 Web 实际创建的会话，恢复历史及文件变更，再由 Android 续聊，三者均正确回复先前文件中的标记。
- 内置浏览器亲自完成三后端的真实读取、写文件、Claude/Grok 允许审批、变更及补丁查看；重载 Grok 后恢复完整正文、审批状态、补丁和实际模型。真实适配器检查另覆盖三者续聊与停止恢复、Claude/Grok 拒绝写入、管理器重建，以及 Claude 问题答复。
- 本机实际返回：AGY 选择 gemini-3.8-flash/medium，但没有提供实际模型名；Claude 入口返回 grok-4.7；Grok 默认自定义入口返回 grok-4.6。账号额度窗口没有对应可靠接口，仍显示缺失，不推算余额。

原生实测前两次断言失败分别来自未合并回答分片、未识别已有的活动折叠摘要；修改用例读取方式后通过，失败日志保留。Grok 的失败回合保留在隔离记录中：曾出现回答截断、询问权限继承本机默认值和续聊 401；分别修复后复测。一次拒绝测试中模型未调用工具而直接回答“已拒绝”，该回合不计作审批覆盖；另一次已观察到明确拒绝回执且文件未变。普通断言通过不等同于真实模型覆盖，以上两类证据分别记录。

## 交付范围

正式安装及在线 APK 一致性见 `artifacts/interaction-0.6.143/deployment.json`。本轮没有安装实体手机，原生检查运行在隔离模拟器包名。AGY 的逐条审批和图片输入、Grok 当前 ACP 的图片和计划切换、未提供的账号额度均不能伪装成 Codex 的对应能力。本网关创建的外部会话持久化及恢复已验证，未新增各 CLI 独立历史库的自动导入。

此前公网只授权 Codex/AGY；Claude/Grok 公网扩大范围尚待本轮确认。局域网三后端使用现有认证与工作目录限制。验证 ZIP 只收录精选日志、截图和合成检查结果，不包含账号配置、Token、完整 CLI 初始化信息或本地状态数据库。
