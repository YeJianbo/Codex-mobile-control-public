## 本次改动

Android 前台通知和系统通知使用同一个摘要实现。定向实时订阅不再被误判为没有答复；非当前会话完成后异步读取该会话最近两轮，操作详情延迟加载，不改变订阅焦点。摘要兼容不同来源的结束事件 ID，按轮次取答复，忽略空文本覆盖并正确处理完整快照。无法取得正文时使用“打开会话查看结果”。

引导入口从实际活动执行器能力取得。AGY ACP 不再因为名字相同而误显示 CLI 的能力，其他 ACP Harness 保留已有排队流程。ZCode 使用自己的命令协议，确认接受后才发布用户消息；上游回退到原生队列时，保持该执行进程，直到队列清空且对应轮次结束。Grok 不再把其他 sessionId 的更新或回放正文归入当前会话。

## 原生子代理剩余工作

ZCode 原生子代理已在 0.6.175 接入，详见 `zcode-integration.md`。生命周期、工具嵌套事件与父会话最终结束分别处理，关闭子代理保留用量。

其他 Harness 要从各自原生协议提供的子任务 ID、父子关系和取消能力适配；当前 ACP 适配器主要收到工具记录，不能仅凭工具名称伪造可打开或可停止的独立会话。此项尚未完成，不属于本次通知和引导修复的已交付范围。

## 工具分段与繁忙恢复（0.6.176）

共用工具事件显式携带轮次，正文在工具操作前后使用独立段落 ID。后续到达的工具名称和参数可以更新最初的空记录；DeepSeek、Hermes、OpenCode、官方 Claude / AGY ACP 与 Grok 共用此行为。Grok 也处理只收到更新的工具，并对完成事件去重。

ZCode 同时读取模型流中的完整工具输入、工具生命周期和工具 Part 快照，合并相同调用，结构化结果保留成功 / 失败状态。历史中的 `*_discarded` 尝试不结束轮次；执行器等待自动恢复时，原生失败快照不能替换仍在运行的控制台轮次。

现有“模型繁忙自动重试”开关覆盖 Codex 和控制台发起的 ZCode 任务。ZCode 仅对明确的繁忙 / 容量错误自动恢复，等待依次为 15、30、60、120 秒，此后保持 120 秒，无次数上限。停止立即取消等待；关闭开关最迟在下一次一秒检查时取消。恢复向同一原生会话发送一条带专用输入 ID 的继续指令，保留已执行工具；不用会回滚历史的 `retryTurn`。控制台把该内部继续指令和后续答复归入原轮次，不重复原用户消息。原生 ZCode 客户端仍可能显示这条继续指令。独立桌面发起、控制台仅观察的任务不由这个开关接管。

## 验证边界

通知摘要与受限并发工作队列的 20 项定向检查通过。ZCode 的原生事件转换、引导回退队列、进程退出与计量共 5 项协议测试通过；Grok 的 2 项会话与取消测试通过；AGY 的 3 项引导、恢复与并发检查通过。测试使用隔离协议 fixture，未向真实会话注入消息。Android 真机交互和真实 ZCode 模型生成未验证。
